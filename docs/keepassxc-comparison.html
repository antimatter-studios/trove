trove vs keepassxc-cli

The question that started this: is trove better or worse than keepassxc-cli? The honest answer used to be "different tools, you need both." The parity gap list closed in trove v0.5.0, and v0.6.0 pushes further into what keepassxc-cli structurally can't do — multi-daemon visibility & reaping, CLI↔daemon version-drift detection, and safer secret materialization.

The verdict, first

What changed

Parity, not approximation

Every capability keepassxc-cli had and trove lacked — generic entry CRUD, keyfiles, TOTP, generation & audit, clipboard, merge/export/db-edit — now ships in trove, each verified against the real keepassxc-cli binary on every CI run.

The shape of the difference

Editor vs runtime

keepassxc-cli is a vault editor: you query a file. trove is a secrets runtime: agents, sessions, and process-scoped injection let your machine authenticate with the vault — which upstream refused to build headless.

Where each still wins

trove's moat — the runtime

  • exec <scope> -- cmd — secrets scoped to one process tree, wiped on exit. A shell with a kubeconfig that vanishes when it closes.
  • Headless SSH + GPG agents — keys served from daemon memory; git commit -S works. keepassxc needs the GUI.
  • Unlock-once daemon — one KDF, then instant ops. keepassxc-cli re-runs Argon2 per invocation.
  • File materialization — decrypt-to-disk on unlock, wipe on lock, tmpfs-guarded.
  • git-credential, --json, trove:// refs — CI-native scripting keepassxc-cli has no answer for.

keepassxc-cli still ahead

  • Maturity — years of audits, packaging everywhere, a large user base. trove is months old.
  • XML / CSV import — trove exports both but only imports via keepassxc (no public XML parser upstream in the kdbx crate).
  • The GUI — browser integration, autofill, deep visual editing. trove-desktop now opens real .kdbx vaults with a system tray and resizable panes, but it's young next to KeePassXC's mature desktop.
  • Ubiquity of the hardware path — keepassxc's YubiKey support is cross-platform and battle-tested; trove's is Linux-only and hardware-unverified so far.

Honest limits — what "yes*" costs

XML importOut of scope: the keepass crate exposes no public XML→database parser. Export (re-importable) ships; import stays with keepassxc-cli.
YubiKey / macOSThe feature builds and is CI-tested on Linux only — upstream pins a USB backend that doesn't compile on macOS. Hardware round-trip is verified by a software provider; a physical-key test ships but is unrun.
Steam TOTPThe non-standard 5-character Steam variant isn't implemented; standard RFC 6238 (SHA1/256/512, 6–8 digits) is.
Secure eraseexec/materialize wipes overwrite-then-unlink; on copy-on-write / wear-leveled storage that isn't a guarantee — the same caveat KeePassXC carries. tmpfs is the real mitigation.

Interop isn't a smoke test: trove-authored vaults are read back field-for-field by keepassxc-cli (including merge-result equivalence and re-imported XML), and keepassxc-authored vaults round-trip through every trove command — TOTP codes matching in the same 30-second window, composite keys opening on both sides.
